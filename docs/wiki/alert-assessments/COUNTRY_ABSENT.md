## What the rule checks

Input is the beacon table `s->beacon_aps[0..beacon_count]` (src/alerts/rules_regulatory.c:76-77), each row's retained regulatory envelope `beacon_ap_t.reg` (parsed by src/reg_ie.c, #101 slice 1). For each AP the rule fires when all hold:

- `!a->reg.country_present` — no Country element (802.11d tag 7) ever seen from this BSSID (line 79).
- `ap_band_label(a->channel, a->channel_source) == "5 GHz"` — band decided by the label helper, never the bare channel number, so 6 GHz numbering overlap cannot trip it (lines 80-81).
- `a->phy != "legacy"` — pre-802.11d gear is exempt, as the TPC rule exempts it (line 82).
- `now - a->first_seen >= COUNTRY_ABSENT_MIN_OBSERVED_S` (60 s) **and** `a->frame_count >= COUNTRY_ABSENT_MIN_BEACONS` (3) — the two-part observation floor, so "absent" needs both elapsed time and readings behind it, not a single missed beacon (lines 86-87, include/sloth.h:2487-2488).

Severity is WARN if `ownership_is_my_bssid()` (the operator's own BSSID) or an SSID match from an unconfirmed BSSID, else LOW (lines 89-91, 130-132). Key: `countryabsent:<bssid>` (lines 96-100). The detail (lines 118-129) prints the BSSID, SSID (or `<hidden>`), channel, the tag-7/802.11d reference, the **threshold** floors `>=60s` and `>=3 beacons` (not the live seconds or beacon total — a moving number in the detail would change the signature every tick and emit an alert.update every 60 s for every country-less AP in range, so the floors are printed instead, comment lines 112-117), the "heuristic, no advisory ... not proof of a rogue" caveat verbatim, a malformed-element note if `a->reg.malformed_country > 0` (a malformed element is a different statement from an absent one — the AP tried), and the ownership tail. Technique is deliberately empty: this is a posture/exposure finding with a real basis but no ATT&CK behaviour, pinned by `tests/test_research_corpus.c :: test_uncitable_kinds_with_a_real_basis_are_still_cited`.

## The attack

There is no attack per se — the finding reports a departure from what a clause leads one to expect. IEEE 802.11d (2001, folded into 802.11-2020 §9.4.2.8, §9.3.3.2, §11.8) added the **Country element** so a BSS can tell its stations which regulatory domain they are in: a two-letter ISO 3166-1 code plus subband or operating triplets, carried in Beacon and Probe Response frames [3][4]. An AP includes it whenever `dot11MultiDomainCapabilityActivated` or `dot11SpectrumManagementRequired` is true [4]. In 5 GHz the second is the important one: nearly every regulatory domain requires spectrum management — radar detection (DFS) and transmit power control — on the channels where radar operates (52-144), so a conformant 5 GHz AP names its domain [4]. hostapd does not send it unless `ieee80211d=1` and a `country_code` are both set ("default: 0 = disabled", "country_code setting must be configured") [5], and stripped OpenWrt images that rogue kits are built from omit it [1]. That is why the #101 issue calls a country-less 5 GHz AP "the cheap, high-specificity tell for a lab-built rogue": commercial and consumer 5 GHz gear ships with a domain configured, because without one it may not use the DFS channels at all [1]. The finding is a compliance/posture signal that *corroborates* a hand-built AP in the right context; it never asserts an adversary.

## Evidence that proves it

The detail (above) names the BSSID, SSID, channel, the floors crossed, any malformed-element count, and ownership. No per-alert pcap: `fire(...)` is called with `match_ip = NULL`, `match_port = 0` (line 132) — the evidence is the 802.11 beacon stream (L2), not an IP flow. The substrate is the `beacon_ap_t` row and its `reg` envelope, visible in the beacons view / `[b]` detail. JSONL `alert`/`alert.*` records carry `key`, `detail`, `sev`, no `technique` field (dropped because empty, src/jsonl.c:522-526 and docs/wiki/jsonl-schema.md:298), and the observations/evaluations split — the number that means something here is `observations` (~1 per incident), not `count`/`evaluations` (ticks held; src/jsonl.c:574-575).

To call it real, the reader should see, over at least 60 s and 3 beacons from the one BSSID, Beacon frames carrying no tag-7 Country element at all (not a malformed one — the detail distinguishes these), on a 5 GHz channel, from non-legacy PHY. What refutes the rogue reading: the AP is known operator or vendor gear simply configured without a country code (very common), or `phy == "legacy"` (exempt), or a Country element that was in fact present but malformed (the detail says so, so the operator does not hunt a missing config line that is present and broken).

## Benign causes

The dominant cause is benign: an AP deliberately or accidentally run without 802.11d — hostapd's default-off state [5], OpenWrt without a configured country [6], travel routers, APs set to a "world" regulatory mode, or firmware that simply never enables the element. None of these is an attacker. The repo corpus is explicit that no CVE or advisory exists and the finding is non-compliance, not hostility [1]; the standard itself [3][4] says nothing about rogues. Distinguishing a benign country-less AP from a rogue one needs the context the rule does not have: is the SSID impersonating a known network (then WARN via the SSID-impostor path), is the BSSID new to the environment, does it pair with other rogue tells (DFS_MASKING, evil-twin episodes). On its own it is a LOW housekeeping note.

## Assessment

Severity is correctly LOW: a posture fact, raised to WARN only when it touches the operator's own identity. The empty ATT&CK technique is correct — there is a real, citable basis (the 802.11d clause) but no adversary behaviour to name. On the reference host the 23.3M fires on 182 keys look alarming but are an artifact of the per-tick evaluation counter: 182 country-less 5 GHz BSSIDs (ordinary in a dense band) each re-evaluated ~4x/s for hours. The design already prevents this from becoming a JSONL firehose — the still detail keeps `observations` at ~1 and throttles `alert.update` to once per 60 s per AP (the exact "change-only emission" discipline in AGENTS.md). So the correct action is not to tune the engine but to read the right field: consumers should treat `observations`/`alert.update`, not `count`, as the event tally. If 182 LOW rows are visually noisy, the lever is view-level filtering of LOW findings, not a threshold. A responder treats a COUNTRY_ABSENT row as "check this AP's configuration/identity," not "respond to an incident": on the operator's own AP, set a country code and enable 802.11d [5][6]; on a BSSID carrying the operator's SSID that is not the operator's, locate and report it.
