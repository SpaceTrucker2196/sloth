The non-negotiables

Philosophy.

Sloth is Citizen SIGINT: an open, receive-only tool that lets a private citizen see and understand the radio spectrum around them. Six rules define what it is allowed to do. They are not preferences and they are not negotiable per feature. They are what makes sloth trustworthy to run on a sensitive segment: the signals it observes were already there. Lose that and the tool is just another offensive fork.

RULE 01

Passive only.

Sloth never crafts and sends a frame onto a network it is monitoring — no injected packets, no probe requests, no deauthentication, no beacons, no ARP poisoning, no port scans. That is the one absolute: no flag, build option or deployment mode turns it off. What it observes, it observes passively.

What it offers, it may offer over the network, opt-in and announced. Nothing below is on by default: --allow-active sends a reverse-DNS query for an address it already saw and asks the kernel for a passive scan; --hop retunes sloth's own monitor interface; a routable --data-socket serves observations to whoever connects and is advertised over mDNS. --strict locks the first and last of those off for the run. One write is neither opt-in nor announced, because it is inherent to capturing at all: libpcap sets promiscuous mode when the handle opens, which changes what sloth's own NIC accepts and never what the segment carries. MISSION.md §2 is the authority.

Monitor-mode interfaces must be set up externally by the operator before sloth starts (using iw, airmon-ng, or the tool of your choice). Sloth attaches to whatever interface is already in monitor mode and starts watching. It never asks the kernel to change link state on its behalf.

RULE 02

No active key recovery.

Sloth never runs a passphrase against a captured handshake. It never calls hashcat, aircrack-ng, John, or any cracking library. It never decrypts a frame it captured.

It does capture EAPOL / PMKID material and export it in hashcat-22000 format — so the operator can run a crack themselves, offline, on hardware they own, against a target they're authorised to test. That step is the operator's responsibility, on the operator's clock, with the operator's legal cover — not sloth's.

RULE 03

Vulnerabilities flagged, not exploited.

Sloth detects a wide vocabulary of weak / hostile patterns, emits an alert, and (optionally) writes a per-flow pcap snippet. It never follows up with an active step — no MITM, no session hijack, no replay, no credential harvesting.

  • WEP, WPA-TKIP, MFP-off
  • Weak TLS (SSLv3, TLS 1.0/1.1)
  • Attack-tool User-Agents
  • Evil twins (same SSID, OPEN sibling)
  • Rogue DHCP servers
  • DGA-style DNS qnames
  • Deauth floods
  • KARMA / Pineapple-style behaviour
  • dnscat / iodine DNS tunnels
  • ARP spoofing
  • Probe-request floods
RULE 04

White hat only.

Sloth is built for:

  • Defenders monitoring their own networks
  • Blue teams running authorised SIGINT in a SOC
  • Incident responders triaging a compromised host
  • Researchers in a lab they own
  • CTF and training environments
  • Security-aware travellers who want to know what the café Wi-Fi is doing

It is not built for surveillance of third parties, harassment, stalking, or any operation against a network the operator is not authorised on.

Receiving broadcast signals (beacons, probes, BLE advertisements, ADS-B, APRS, GNSS) needs no permission: they are sent in the clear to anyone in range. Observing a network’s own traffic needs authorisation, and joining it is that authorisation: authenticating through its WPA login with credentials its owner issued or published implies permission to observe it. A guessed, cracked or borrowed credential is not.

RULE 05

Operator owns the consequences.

Sloth surfaces information. What the operator does with that information — file an incident, reconfigure an AP, brief a client, walk away — is outside sloth's scope.

The tool is honest about what it sees and silent about what to do.

RULE 06

Radios, not people.

Sloth reports that a device is present, how it behaves technically, and where it is or how it moves relative to the sensor. It never infers who uses a device, or that person's activity, purpose or routine.

A correlation across MAC rotations is a hypothesis about a radio, never an identification of a person. (Set by the operator on 2026-11-25.)

LAWFUL USE

The terms sloth is built for.

  • Receive only. The one helper that transmits, sloth-va, talks only to the operator's own Victron devices and is off by default.
  • No decryption and no content interception.
  • No key recovery.
  • Collect only what is broadcast in the clear.
  • Remove third-party identifiers — other people's MAC addresses, network names, call signs — from anything you share.
  • The law where you are is your responsibility. In the U.S. that includes, for example, FCC rules and the ECPA. This is not legal advice.
OUT OF SCOPE

What sloth deliberately won't do.

If you're tempted to add a feature because it would be useful — port scanning the LAN, sending a deauth to test detection, auto-cracking the captured handshake — stop. That feature belongs in a different tool. Sloth's value is being trusted to be passive: an operator can run sloth on a sensitive segment without changing the segment.

  • Active reconnaissance (port scan, host sweep, OS fingerprint via probes).
  • Frame injection of any kind.
  • Online cracking, dictionary attacks, password-spray, credential validation.
  • Decrypting anyone else's traffic.
  • Identifying, profiling or following a person.
  • Network configuration (DHCP server, DNS resolver, firewall rules).
  • Any "honeypot" mode that responds to inbound traffic.
  • Remote-control surfaces of any kind. No command channel, no "do X" RPC, no inbound-configuration endpoint, no plugin loader, no shell-out. Sloth refuses to act on instructions it receives over the wire.

About

Citizen SIGINT: an open, receive-only tool for the radio spectrum around you — Wi-Fi, Bluetooth and BLE, ADS-B, APRS, GNSS, SDR sweeps and the host network. Live views, alert rules with written assessments, and a JSONL stream you can pipe into any SIEM. Radios, not people. Built in C99 for Linux.

Run sloth only on networks you have explicit authority to observe, and follow the law where you are. MISSION.md has the terms.
