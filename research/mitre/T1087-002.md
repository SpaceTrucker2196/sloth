# T1087.002 — Domain account discovery

Enumerating a directory to learn who and what exists: users, groups,
computers, service principals, trust relationships. It is the first step
of almost every Active Directory intrusion, because the attack path is
not knowable until the graph is.

Tools that do this — BloodHound and SharpHound most prominently — pull
the directory comprehensively rather than selectively. That bulk is the
signal.

## Why sloth cites this

`ALERT_TYPE_LDAP_SEARCH_FLOOD` fires on **LDAP search volume from one
source in a window**.

It is a rate rule rather than a content rule for a deliberate reason:
the queries an enumeration tool sends are individually ordinary. Asking
for all users is a legitimate operation that a directory is *for*.
What distinguishes collection from use is that collection asks for
everything, from one place, in a short time.

Mapped to T1087.002 rather than to a brute-force technique because
nothing here is an authentication failure — the adversary is already
authenticated, often as an ordinary user, and that is precisely why the
enumeration succeeds.

## What it does not say

**Legitimate bulk readers exist and are common.** Identity-sync
connectors, monitoring agents, backup software, address-book clients and
vulnerability scanners all pull the directory in bulk on a schedule.
Every one of them will trigger this rule, and the operator's job is to
know which sources are supposed to.

**It cannot see LDAPS content.** A search over TLS is invisible to
sloth; only the connection is observable. An adversary using LDAPS —
which is increasingly the default — produces nothing here.

**Volume is not intent.** This alert says a directory was read heavily.
Whether that reading was reconnaissance is a question about the account
doing it, which is a fact in the directory's own logs rather than on the
wire.
