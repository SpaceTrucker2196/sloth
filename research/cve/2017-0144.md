# CVE-2017-0144 — EternalBlue, and why SMBv1 is the finding

A remote code execution flaw in Microsoft's SMBv1 server, patched in
MS17-010 in March 2017 and weaponised as EternalBlue. It is what
WannaCry and NotPetya propagated with, and it remains one of the most
consequential network vulnerabilities of the last decade.

Microsoft has deprecated SMBv1 and removed it from default installs.
Its continued presence on a network is almost always an artefact —
legacy NAS, an old scanner, a printer — rather than a decision anyone
would make today.

## Why sloth cites this

`ALERT_TYPE_SMB1_USE` does not detect EternalBlue. It detects **SMBv1
being negotiated at all**, which is a deliberately broader and more
useful claim.

The protocol version is visible in the negotiate exchange without
decryption or reassembly. Sloth reports it because the exploit's
existence makes the protocol's presence the finding: a host speaking
SMBv1 is a host on which this class of vulnerability is reachable, and
that is actionable regardless of whether anyone is currently exploiting
it.

Mapped to T1210 (Exploitation of Remote Services) rather than to a
lateral-movement technique, because what sloth observes is the exposed
surface, not its use.

## What it does not say

**It is not an exploit detector.** An SMBv1 negotiation is overwhelmingly
a legacy device doing its job. Reading this alert as an attack in
progress would be wrong nearly every time it fires.

**A patched host still triggers it.** MS17-010 fixed the vulnerability;
it did not remove the protocol. A fully patched Windows server with
SMBv1 enabled for a legacy client is not vulnerable to this CVE and will
still be reported — correctly, because SMBv1 has since accumulated other
reasons to be gone.

**Absence is not assurance.** Sloth reports the negotiations it
observed. A host that speaks SMBv1 only to one client on a VLAN sloth is
not on produces nothing here.
