# CVE-2023-45866 — unauthenticated HID peripheral accepted by a host

NVD (API record, read 2026-10-21): "Bluetooth HID Hosts in BlueZ may
permit an unauthenticated Peripheral role HID Device to initiate and
establish an encrypted connection, and accept HID keyboard reports,
potentially permitting injection of HID messages when no user
interaction has occurred in the Central role to authorize such access."
Published 2023-12-08, CWE-287, CVSS 3.1 base 6.3
(`AV:A/AC:L/PR:N/UI:N/S:U/C:L/I:L/A:L`).

Apple HT214035 (iOS 17.2, 2023-12-11) lists it under Bluetooth: "An
attacker in a privileged network position may be able to inject
keystrokes by spoofing a keyboard", credited to Marc Newlin of SkySafe.

The researcher's proof of concept (hi_my_name_is_keyboard, README, read
2026-10-21) pairs "an emulated Bluetooth keyboard" and injects
keystrokes "without user confirmation" against Android (~4.2.2 and
later before the 2023-12-05 patches), Linux with "the default
configuration of BlueZ 5", macOS before 14.2 and iOS before 17.2. It
presents as a **Bluetooth Classic** HID keyboard, class of device
0x002540, tested from "an Ubuntu 22.04 host with a Broadcom-based
Bluetooth adapter".

## The identifiers the rule reads

Bluetooth SIG Assigned Numbers, read 2026-10-21:

- `core/appearance_values.yaml`, category 0x00F "Human Interface
  Device", subcategories 0x01 Keyboard, 0x02 Mouse, 0x03 Joystick,
  0x04 Gamepad, 0x05 Digitizer Tablet, 0x06 Card Reader, 0x07 Digital
  Pen, 0x08 Barcode Scanner, 0x09 Touchpad, 0x0A Presentation Remote.
  An appearance is (category << 6) | subcategory, so HID is
  0x03C0 (generic) through 0x03CA.
- `uuids/service_uuids.yaml`: "uuid: 0x1812 name: Human Interface
  Device id: org.bluetooth.service.human_interface_device".

## Why sloth cites this

`ALERT_TYPE_BLE_HID_UNEXPECTED` fires on the advertising shape of an
injected keyboard: a HID appearance or the 0x1812 service from a public
address whose OUI is in the Hak5 or Espressif table
(`src/wifi_oui_attacker.h`), or HID appearances arriving on several new
random addresses within one window. T1200 (Hardware Additions): a
keyboard that should not be there.

## What it does not say

- **This is not an exploit observation.** The CVE is the host
  accepting an unauthenticated peripheral. sloth sees no pairing, no
  connection and no keyboard report; it never connects or reads GATT.
- **The public PoC is BR/EDR, not LE.** An LE HID advertisement is the
  same class of device announcing itself over the other transport. The
  rule corroborates; it never confirms.
- **The OUI tables are narrow on purpose.** Espressif silicon ships in
  legitimate keyboards and remotes too; a public Espressif address
  advertising HID is unusual, not hostile. Random addresses carry no
  OUI at all, which is why the second form looks at rotation instead.
- **The rotation threshold has no basis** in any document here.
  `ble.hid_rotate_addrs` (3) inside `ble.hid_rotate_window_s` (900 s) is
  a judgement, gated so the first window of a run — when every address
  is new — cannot qualify.
